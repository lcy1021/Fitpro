# iOS 主屏幕灵动岛背景：排查复盘与 v51 解决方案

## 结论与验收

2026-10-13，v51 发布后用户明确反馈「可以终于解决了」。本次首开顶部白条问题已由用户真机确认解决。无需重新添加桌面图标。

关键是将这类安装态的**初始滚动位置设到实测顶部预留之后**，让场景图进入原生状态栏后方；并移除上一版为抵消滚动而增加的留白。透明背景本身不足以解决首开与手动滚动的差异。方案基于当前设备证据，有明确触发条件，不是所有 iPhone 通用的固定 60px 偏移。

验收来源是用户对已发布版本的反馈；本机未直接调试该手机的 WebKit 合成层，也未新增一张修复后的原生截图。结果已确认，底层解释仍是实测与源码支持的判断。发布时的 `release-verification.json` 中 `nativeStatusBarVerified: false` 保留为当时快照，本节记录后续真机确认。

## 后续首开跳动（v52）

用户后续补充“先白条，再自动向上移动”。v51 的真机确认针对最终贯穿效果，并未覆盖这一时序缺陷。v52 将共用定位提前到入场层淡出之前，具体原因与逐帧验证见 [启动呈现 QA](../startup-reveal-v52/README.md)。复用此方案时，既检查最终位置，也检查首页露出的第一帧。

## 证据及修改前差异

用户 v50：screen 430×932、inner/client/visual 430×873、safeTop 0、safeBottom 34、scale1、offsetTop0，主屏幕两种检测均 true。首开 scroll1 / heroTop0；手动 scroll72 / heroTop−71。版本已经到达设备且 scrollTo 已执行，白栏仍在。必要几何值写入维护记录，整份私人连接日志不入库。

[WebKit insetClipLayerRect](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/page/LocalFrameView.cpp) 用 inset−scroll 计算顶部裁剪位置，并在 scroll≥inset 时归零。这与 59px 白栏、1px 无效、72px 可显示场景的用户证据一致；不能声称已经在用户系统构建中直接调试验证。

可执行差异：取消额外 1px padding，符合受限视口条件时真正滚过 59px 预留（目标60），而非用负 margin 将图片移到仍被原生裁剪的区域。页面将出现用户喜欢的轻微滚动效果。完整3:4场景、主体姿态／服装、手写句／线、道具、背景和下缘渐隐不变。标题及首卡随正常滚动上移，填补原先屏幕顶部多出的预留；底部固定导航不偏移。角色切换按钮仍需避让原生顶部，使用一个默认0的语义 token。

## 以后遇到相似问题的排查顺序

1. **区分首开与滚动。** 从原桌面入口打开，分别观察完全置顶、轻滚后、回顶和切页；先确认是不是同一安装态仅在首开显示纯色栏。
2. **先采集实际几何与版本。** 使用「记录 → 设置 → 复制连接诊断」检查版本、standalone、screen／inner／client／visualViewport、安全区、scrollY、heroTop、首开和首次手动滚动快照。不要把 `safeTop=0` 等同于屏幕上没有原生预留，也不要把 UA 中兼容用的 OS 字段单独当作系统版本结论。
3. **排除未更新与图片问题。** 核对线上资源及设备版本；检查图片是否解码、原图是否正确。网络日志正常不能证明顶部布局正常。只保留排查需要的尺寸，整份私人连接日志与截图不上传公开仓库。
4. **按条件复用当前 helper。** 首开、切页、回顶、前台恢复共用同一起点。不要另写页面补丁，不硬编码 59／60／72，不叠加旧负边距或补偿 padding。
5. **检查交互边界。** 普通浏览器、正常全屏、横屏、缩放、键盘和已报告顶部安全区不应套用该偏移；阅读中、拖动／回弹、弹窗、输入时不得被拉回顶部。角色切换控件单独避让顶部。
6. **分三层验收。** 网页回归 → 发布文件核验 → 原桌面入口真机确认。即使前两项通过，也不能提前宣布原生白条解决。若新设备不满足当前条件，先取实测再决定方案，不扩大猜测范围。

## 当前代码及适用边界

- [`index.html`](../../../index.html)：`pageViewportSnapshot / pageViewportDiagnostics` 提供诊断；`prepareHeroScrollStart` 注册安装态事件；`heroScrollStartOffset` 计算起点；`restoreHeroScrollStart` 保留阅读和交互状态；`scrollToPageStart` 供显式切页回顶复用。
- [`tokens.css`](../../../design-system/tokens.css) 与 [`components.css`](../../../design-system/components.css)：`--ds-native-top-inset` 默认 0，受限安装态用于保护 `.ds-page-hero-role`；不用于给整页补回空白。
- 触发条件：iOS UA 且主屏幕模式；竖屏；屏幕与网页宽差不超过 1px；屏幕高减网页高在 20–80px；根节点 `scroll-padding-top`（对应安全区）未报告正值。若有 visualViewport，还要求 scale 与 1 的差不超过 0.01、高度与 innerHeight 差不超过 1px、offsetTop 绝对值不超过 1px。
- 满足条件时 `target = ceil(screen.height - innerHeight) + 1`，否则为 0。正常阅读位置大于等于 target 时不重置；180ms settle 与 scrollend 等事件负责在交互结束后检查。v51 仍沿用当前透明根画布／同场景背景分层与 `viewport-fit=cover`、`black-translucent` 基础设置，不应抽走其中一段就认为效果等价。
- 这是一项针对实测布局的兼容处理。高度差本身不是通用安全区 API；新系统、新窗口模式或其他设备需要独立核对。若未来改为独立滚动容器或全新的头部布局，应重做这组验证。

本次验收记录只改文档，应用与缓存版本继续为 v51。
