# Design System 1.0 与图稿复核 · v36

## 为什么重新核对

用户要求设计系统，随后指出必须按照确认的视觉稿调整界面。v35检查侧重字号、功能及局部布局，没有把记录首屏信息顺序列为阻断差异。本次先打开[确认稿](../soft-meal-design/selected-design.png)与实际截图，调整代码，再提取共用组件。早期橙色规范是历史参考，正式入口是[蓝粉设计系统](../../design-system.md)。

## 修改与原因

- 记录先显示标题、角色切换、餐次详情、活动；日历和连续打卡随后。所有日期选择、趋势、身体输入和共享设置仍在，日期随选中日更新，重复的详情标题不再可见。
- 今日餐图106×72改为160×94；标题角色96×96、双人160×96；常规标题区112px、320px为88px。计划与实际标签使用角色强调，tab轨道轻染、选中表面与阴影，时间线节点10px，无选中下划线。
- 首次放大饮食图挤压「下午加餐」为两行。同屏对照发现后修正：常规餐名最小64px、图88×64、间隔6px；320采用紧凑网格，热量留在标题同组第二行，完整餐名不被挤压。
- `.ds-section-heading / .ds-role-tabs / .ds-checkin` 与App旧类名共用规则。基础卡、按钮、餐次及历史组件进入components，颜色/主题/身份进入tokens；字号、间距、圆角、触摸区、动效有语义变量。
- 展示页reset的 `font:inherit;color:inherit` 曾覆盖操作字号和未选灰色，改为仅继承字体家族。复测打卡12px、未选#64748B。主题过渡中捕到的中间色截图已重拍稳定画面。
- App和组件页真正加载同一CSS；展示页只调整说明文档排版，交互不调用后端、不保存个人数据。旧设计参考、主设计文档和AGENTS一起指向正式规范。
