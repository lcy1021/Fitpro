# 方案一视觉细节补齐 · v37 / Design System 1.1

## 漏项原因与修复

v36 虽统一了字号/组件并调整记录顺序，却把明确出现在确认稿里的云朵、角色姿势、手写文字当作P3；复用旧头像/情绪图，未做逐项素材清点。用户反馈后重新按[确认稿](../soft-meal-design/selected-design.png)修复，旧报告见[v36存档](v36-review-archive.md)。本轮把背景、辅助文案、主体、道具与小装饰列为必须验收内容，不以“已建立设计系统”代替图稿还原。

| 视觉项 | v36 | v37 |
| --- | --- | --- |
| 面板背景 | 页面渐变，模块无云层面板 | `.ds-scene` 蓝粉轻染、共享真实透明云层、细边缘 |
| 今日餐头/正文 | 大片平色头、直白正文 | 云层头、浅色边缘、内层圆角正文、虚线实际分隔 |
| 今日标题图 | 普通跑步头像，无小字 | 两角色跑步图 +「好好吃饭／就是爱自己」+小粉心 |
| 我的一天标题图 | 旧吃饭表情，碗不突出 | 蓝粉新吃饭图，白碗/勺子/星星可见 |
| 记录标题图 | 双人图无三颗爱心 | 保留蓝左粉右躺趴，补爱心和柔和高光 |
| 早餐/午餐图 | 小燕麦/普通面碗 | 香蕉片/蓝莓/牛奶、面碗和侧面细节 |

计划热量和保存记录始终由实际业务计算；生成图上的范围不硬编码。所有截图使用本机合成数据，不加载生产config、不存储私人资料。用户要求模块17px/800、餐内12/14/16px优先于生成图中的大文字。

## 图像素材

8张透明WebP共278KiB，独立 `detail1` 版本，图片缓存仍 `duofit-images-v1`；各页面只按需加载，云层共用一份，无启动全量预载。所有新资源均为RGBA、alpha0–255，详见[asset-results.json](asset-results.json)。8张均已放入真实组件，无占位盒/整页截图裁切/CSS插画。PNG源及内置image_gen提示记录在[assets/](assets/)。渲染不是逐像素复制，早餐比稿更写实；主体/构图/道具已补齐。

## 迭代与布局修复

1. 首轮新增面板减小内部宽度，390饮食热量kcal换行；常规餐图72×64、热量不换行，320同组第二行网格保持完整餐名。
2. 组件展示页原有媒体规则改写产品图片尺寸，已移除。产品组件实际规则由components唯一维护。
3. 云层灰色阴影偏明显，浅色改用brightness(1.3)/.55，深色brightness(.7)/.12。角色浅染同套tokens。
4. 初始抓图捕到导航颜色过渡，最终四张参考截图在颜色稳定后重新抓取，未把过渡中间色当作设计结果。
