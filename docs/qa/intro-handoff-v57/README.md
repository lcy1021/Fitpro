# v57 引导与首页的顶部交接

## 问题和证据边界

用户反馈v56修复引导背景穿透后，退出引导仍见灵动岛轻闪。当前根节点从初始就是透明并加载同一首页图，但引导继承`.pick { position:fixed; inset:0 }`，具有全屏不透明渐变，整体淡出后display:none。

[WebKit 305546](https://bugs.webkit.org/show_bug.cgi?id=305546)记录固定顶部背景参与状态栏取色；[302272](https://bugs.webkit.org/show_bug.cgi?id=302272)记录fixed弹层可改变顶部取色。它们支持本轮排查方向，不证明用户系统上这一帧的唯一根因。未连接用户手机原生合成器，因此真实闪帧消除仍待验收。

## 修改前执行差异

先查看v56同屏和捕获430×932、run态当前图。目标：蓝粉独立底图、小字、两个原角色、姿态/服装/道具/点阵/跑道及选择交互全部保持；只去掉固定层对顶部采样的参与，不挖透明缺口、不恢复首页大人物穿透。

## 改动

- 引导改为文档absolute定位，`--ds-entry-scroll-top`与当前scrollY一致，视口内坐标仍为0。
- 配置加载前的受限iOS滚动、打开动画/身份选择、首页就绪定位及resize同步锚点；选择阶段输入可能触发文档滚动，同步锚点但不强制滚回。内部仍可滚动，外部锁定逻辑保留。
- 根背景持续透明、同一首页图片预加载、v51设备守卫与起点、v52淡出前定位保留。
- 诊断增加entryLayer位置/打开状态。无额外计时滚动、图标改动、数据迁移或config改动。
- 核心文件/诊断/展示页/本机预览/SW v57；图片缓存仍duofit-images-v1。

## 验证

- 320/390/430 × 蓝粉 × 浅深，48个动画阶段，首页底图换成洋红后引导截图仍完全相同。
- 430浅色蓝色修改前后截图字节相同，说明背景、文字、角色、装饰没有变化。[同屏](comparison.html)。
- 普通及模拟受限iOS各8条启动路径；粉色深色缓存/跳过追加2条。初始与淡出期间引导均absolute、顶部0、根背景透明，原生起点模拟值始终60。
- 长页面打开选择、320×480短视口resize、角色选择、可选输入和引导内部滚动。
- design-system、scenarios、sw-cache、viewport-diagnostics浏览器回归。
- 浏览器检查不包含真正iOS状态栏，无“真机不闪”的验证结论。
