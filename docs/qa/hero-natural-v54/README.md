# v54 自然磨砂与启动白帧处理

## 用户要求与修改前差异

用户指出 v53 实装磨砂不自然、手机首开灵动岛仍闪白，要求按附图的连续前景效果调整。参考保存为 approved.png；同视口 v53 实装为 before-light-430.png / before-dark-430.png。

- v53 的草地纹理仅在标题高度附近叠加，且 backdrop-filter 不会模糊伪元素自己的图片，形成有细碎花纹的横向色带。v54 扩大羽化范围（信息区上方64px），纹理本身4px模糊、背后10px模糊，浅色底色混合64%，下缘渐隐。
- 顶部人物、湖岸、帽子、衣服、腿鞋和动作、原手写文字／独立下划线不换图；只改变文字区的合成。四页共用羽化，今日沿用已有独立草地素材，其他页保留各自环境。
- 标题36px／小屏32px、右侧日期与同步、信息位置、首卡位置和真实起身计数保持用户已确认布局。

## 启动证据与修复范围

v52/v53 只在首页入场层淡出前定位，没有覆盖更早的启动阶段。入场层仍是 `background:var(--bg)` 的不透明奶油底，且配置脚本阻塞时滚动仍为0。这两项代码事实可以复现；用户原生白帧具体来自哪一帧，仍未直接抓取手机录屏／合成器，不能声称完整根因已证实。

v54：
1. 入口文档样式就提供浅蓝天空／深蓝天空底色，入场固定层用渐变背景且 background-color 透明，移除顶端不透明奶油底。
2. 在 config/auth 脚本之前执行受限 iOS 初始定位，并提供仅启动期间的可滚动高度。计算复用 v51 已确认规则，不新增固定60px设备假设。
3. 保留首页淡出前的定位，避免应用渲染改变可滚动高度。正常浏览器、覆盖安全区、键盘、缩放与横屏仍受原守卫限制。
4. 诊断新增 earlyStart（target、scrollY、before-config），不记录用户数据。

这是更早完成定位、取消页面可控白底的修复，不是零滚动实现。无法用桌面模拟承诺 iOS 打开网页之前的系统快照也不闪。WebKit 有[冷启动白帧报告](https://bugs.webkit.org/show_bug.cgi?id=311569)，仅作为区分系统首帧的参考，不能据此断言用户就是同一系统故障。

- design-system、scenarios、meal-ui、sw-cache 通过；v53旧壳缓存升级迁移保留图片。
- comparison.html / comparison.png 同屏展示确认稿、v53、v54；没有伪造原生状态栏。手机闪白最终结果待真机验收。
