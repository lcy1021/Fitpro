## 人物形象系统（以后制作新姿态的验收标准）

原版基准为 `assets/login/hus-running.webp`、`assets/login/wife-running.webp`、`assets/mood/hus-meal.webp`、`assets/mood/hus-workout.webp` 和 `assets/meal-art/record-couple-v1.webp`；身份注册仍由 `design-system/mascots.js` 管理。

1. **共同身体结构**：头和身体是一块连续、近圆形的云朵体；没有脖子、独立胸腔、细腰或额外的人形躯干。即使坐姿、跑姿或双人互动也不能拉长成真人比例。
2. **手臂**：从云朵体左右外缘直接生出，根部与身体连续；短、圆、末端为简化手掌，不画细长上臂、五指或独立肩膀。举手动作只改变手臂方向，不改变身体结构。
3. **下身**：蓝角色的深蓝白条纹短裤、粉角色的深蓝白条纹运动裙紧贴云朵体下沿；腿从衣物下方出现，短而厚，脚穿原版青色/珊瑚色运动鞋。没有衣物以上的独立躯干。
4. **身份锚点**：蓝角色的深蓝卷发和青色帽檐，粉角色的高马尾和粉色发带；脸部眼睛、腮红、嘴形、云朵轮廓、材质高光与身体比例都要对照原图。只换背景、表情、道具和动作，不另起一套角色。
5. **双人尺度**：同场景时两人视觉体量相近；座椅、桌沿或前景可遮挡腿部，但完整原型必须仍有同一套短腿与鞋，不能把记录页独立画成只有头像的角色体系。

## 动效与实现边界

- 今日：云层远慢近快，角色轻微跑步/呼吸；饮食：窗外光斑、碗边热气；训练：休息日缓慢伸展；记录：册页轻翻、灯光微动。先做 3–5 秒低幅循环，进入页面后保持安静，尊重 `prefers-reduced-motion`。
- 手写句在正式页面应为**可访问的真实文字层**，叠在场景安全区；标题、日期、同步状态也保持 DOM 文本。不要把数据或唯一可读文案烧进图片。长句和 320px 时允许换行，不能盖住脸或系统状态栏。
- 这四张生成视觉稿用于构图确认，**不能直接作为正式角色素材或完整页面截图上线**。正式制作必须从上述原版资产建立每个新姿态并逐项比对，无法达到一致性时先沿用原版姿态；深浅主题、蓝粉身份、320/390px 和休息/训练状态均需实机/浏览器验收。
