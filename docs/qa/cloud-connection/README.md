# 云端连接调查与修复（2026-10-09）

用户在入场动画之后反复遇到“读取档案遇到问题”。此前的本机缓存修复解决了失败时的入口问题；本次调查连接、会话刷新和同步队列。

## 证据与范围

- 截图能确认启动读取失败，不能区分网络、Auth、数据库或前端处理异常。旧版只有统一错误提示，没有用户手机当时的请求状态和耗时。
- 当前工作机对项目基础接口进行了 3 轮只读探测。Auth health 均为 HTTP 200，耗时 1.102 / 0.881 / 0.966 秒；不带用户身份的私人 RPC 均按权限返回 HTTP 401，耗时 1.351 / 1.293 / 1.209 秒。这只证明探测时入口可达，不代表用户手机的网络路径或实际私人查询性能。
- 调查时 [Supabase 状态页](https://status.supabase.com/)显示所有系统正常；这不能排除当天其他时间或单个项目的故障。
- 数据表的私人记录主键是 `(user_id,date)`，周计划主键是 `(user_id,week_start)`，伴侣数据也有家庭/角色/日期索引。对当前两人使用量，没有从 SQL 发现支持“缺少基本索引导致频繁失败”的证据。
- 代码确认存在以下问题，并通过故障模拟复现。不能把它们逐一等同于今天手机的每次失败原因；若继续发生，新版诊断可补足客户端证据，仍可能需要对应时刻的 Supabase Auth/Postgres 日志。

## 结构问题与修复

| 原流程 | 失败影响 | 新流程 |
| --- | --- | --- |
| 手写 token 刷新，没有共享请求或跨页面锁 | 启动、同步、AI 或不同页面可能重复刷新旋转凭据；迟到响应可能覆盖新登录 | 同一实例共用刷新；Web Locks 串行跨页面刷新；读取最新会话；异步结果检查身份归属 |
| 刷新返回任何 400/401/403 都清除登录 | 配置或服务错误也可能被视为会话失效 | 仅明确失效错误码清除登录；未失效的 token 可在预刷新服务暂时失败时继续用于请求 |
| 普通网络/服务错误一次失败即退出；启动失败后 inactive 不参与同步 | 一次丢包放大为整次进入失败，必须手动重试 | 安全请求最多 3 次尝试并退避；启动错误、网络恢复和前台唤醒共用重连入口 |
| 私人上传没有期限；busy 期间忽略新同步触发 | 一个卡住的上传阻塞后续同步；新增修改延后或丢失触发 | 可重复上传设置 15 秒期限；新修改排入下一轮；失败后自动退避重连 |
| 上传完成按记录键清除 dirty | 上传过程中同一条记录又被修改时，新内容也被错误标为已同步，随后可能被云端旧内容覆盖 | 冻结上传快照，确认本机当前内容与快照相同才清除 dirty；否则保留并继续上传 |
| 多个来源触发完整拉取，空闲也每 30 秒读取所有近 120 天数据 | 重复网络请求，扩大与刷新竞争的机会 | 进行中的拉取合并；空闲读取间隔 90 秒，前台唤醒 15 秒内去重；新增记录优先上传 |
| 统一报“配置和建表脚本”错误 | 网络、身份、服务端异常难以区分 | 区分同步/离线/身份/普通错误；保存最近 40 条不含私人内容的本机连接诊断 |

[Supabase 会话文档](https://supabase.com/docs/guides/auth/sessions)说明 refresh token 会旋转，默认重复使用宽限为 10 秒，并处理直接父 token 的响应丢失情形。[错误码文档](https://supabase.com/docs/guides/auth/debugging/error-codes)明确指出大量并发刷新可产生 `conflict`，应检查并发并退避。客户端不应依赖宽限窗口替代并发控制，也不应仅凭 HTTP 403 清除用户身份。

## 重试与数据边界

- 自动重试仅用于读取和已审查为可重复的保存 RPC，以及会话刷新。匿名注册和消耗一次性恢复码的 RPC 不自动重发；一次性恢复也不强制中止，以免制造未知的凭据消耗结果。
- 短暂错误包括网络中断、期限超时、部分 5xx、429 及明确冲突错误。尊重 `Retry-After`；若要求等待超过单轮允许值，则退出当轮，交给后台重连。
- 数据仍直接通过浏览器到 Supabase；这些改动不会修复运营商路由、DNS、TLS 或云端持续故障。没有把尚未同步的记录显示为已同步。
- 空闲时伴侣状态的更新可能等到下一次 90 秒轮询；前台唤醒、重新上线和自己的新增记录会提前触发连接。
- 日志只保存在本机，不传往额外服务。仅记录时间、接口路径（不含查询参数）、耗时、尝试次数、HTTP 状态、错误类别和规范错误码；不记录请求/响应体、token、恢复码、用户 ID、家庭口令或健康内容。
