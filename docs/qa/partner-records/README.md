# 伴侣打卡详情 · v33

## 交互

- 历史日历下的老公/老婆标签改为按钮，显示选择状态，切换后查看同一天该角色的详情。日期变化保留角色选择。
- 本人记录及伴侣记录都只读；打卡仍在今日/饮食页面操作。
- 伴侣可共享餐次状态、实际记录的食物名称/份量/热量、训练完成、起身次数、可选活动。
- 查看伴侣时可「刷新记录」，不清掉未保存的身体记录输入。
- 伴侣已关闭共享、未配对、网络未确认及当天没有记录分别有对应说明。

## 默认共享，个人可关闭

记录 → 设置 → 共享我的打卡详情。双方独立设置，只决定自己的详情是否给已配对的伴侣查看。默认向已配对伴侣共享餐食/活动详情；界面明确说明近 120 天及未来记录的范围。随时关闭，已经看过的内容无法收回。

体重、围度、目标、健康状态、日常身体状态、自由文本与聊天内容不包含在共享详情中。

## 云端与缓存

- 增量 SQL：先 `supabase-checkin-sharing.sql`，再 `supabase-checkin-sharing-default.sql`。新表仅保存家庭/角色的共享开关，default 为 true，FK 关联现有成员，恢复用户 ID 不改变同意；删除成员时自动移除。
- 表开启 RLS，PUBLIC/anon/authenticated 没有直接读写权限；设置 RPC 只根据 auth.uid 找本人，不能指定他人或家庭。
- 读取 RPC 根据同一家庭中的伴侣及其开关决定是否返回详情；显式关闭返回空数组；没有偏好记录时默认共享，未配对不返回详情。日期上限为近 120 天。普通同步只返回共享开关；`fl_partner_checkin_get(date)` 每次只读取选中的一天，避免启动和轮询额外下载伴侣全部历史详情。
- 共享 body 采用嵌套白名单，不转发原始私人 body 或 food.text。JS 也裁剪嵌套字段，显示文字转义。相同日期的请求合并，空记录也标记为已读取，旧请求不能覆盖身份重置后的状态。
- 详情保存在运行内存，不写进本地 profile/store 缓存。重启重新确认；云端读取失败/关闭/身份切换清空伴侣详情。不能收回已经看过的信息。
- 元数据/旧接口缺失时显示待联网确认，不推断已授权或没有打卡。
