# v60 冷启动白屏与静止引导

## 反馈与证据

用户确认从主屏幕图标完全退出后打开，仍有白色画面停留4秒以上，或引导有画面但没有动效。v59 的外部 CSS 延迟测试没有覆盖 HTML 流式下载和关键脚本等待，不能据本机首绘时间宣称真机冷启动已解决。

已确认代码路径：

1. v59 引导 DOM 在约116KB之后；响应先送64KB、尾部暂停4500ms时，900ms无引导/FCP，完整首绘4568ms。
2. 动画只在 config → coach → mascots 串行脚本完成后才启动。脚本各暂停4500ms时，引导已经绘制，但900ms仍为start、角色在画外，未启动动效。实际用户手机的请求日志没有取得，不能断言是哪一个请求当时停住。
3. SW 的必要安装资源包括5,162,508-byte装饰字体，随后还等待场景预热；弱网/失败会拖延新版缓存激活，保留较慢的旧启动路径。线上SW核对为v59，但未取得用户手机当时的控制器版本。

## 修改前清单与范围

打开认可的390px引导图，再从Git `3bf2013:index.html` 复现静止引导；同状态320/390、蓝粉、浅深图用于对照。背景、标题/英文/说明/底部短句、原版双角色身份/比例/衣帽/跑步姿态、点阵/跑道/速度线/星光与跳过均保留。正常run图按前轮同视口基准核对，非角色区域像素一致，旋转角色/投影仍有轻微浏览器栅格化差异。未重新生成或替换角色。

- HTML 约265KB缩至约50KB；引导在body第一项，tokens、entry.css、entry.js生成快照保证先绘制和启动。app.css/app.js从原内联源码分离，业务脚本defer并行下载、按顺序执行，样式非阻塞加载并就绪后才初始化。静态文件仍直接部署，无框架或运行时构建。
- 动画不等业务请求；主流程接管已播放/已跳过的状态，不重新播一轮。等待时继续轻跑/状态反馈；资源失败或8秒后显示重试和复制启动诊断。短屏内部滚动、减少动态偏好保留；配置失败明确停止，不进入旧本机模式。
- SW注册不依赖业务启动成功：正常进入后延迟800ms，异常等待时2600ms独立尝试；新版完整CORE成功后激活。非必要场景预热移至首页打开后，重复预热合并；旧图片缓存保留。缓存版本问答用于诊断，不读取用户数据。
- 手写字体按现有五组固定文案生成14,488-byte WOFF2，字形轮廓/宽度逐字一致，原始母版/许可保留。字集覆盖测试防止新增句子漏字；新增字集需递增素材版本。
- config.js、记录ID/角色格式、UID隔离、共享范围、云端/SQL、未上传数据和已确认iOS定位均保留。核心/SW/诊断/主题预览/组件页v60，设计系统1.10；新增等待/恢复组件使用既有token，展示页可演示失败/重试。
- 启动诊断仅含版本、缓存控制器版本、绘制与资源/阶段时刻、导航字节、安装态/减少动态；不含身份、口令、健康内容、令牌或请求原文。
